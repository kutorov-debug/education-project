# Инструменты, плагины и MCP

## Принцип выбора

Использовать минимальный инструмент, который решает задачу:

1. Локальные проектные файлы и `sources/` — для устойчивого контекста проекта.
2. Веб-поиск — для актуальных открытых источников и прямых ссылок.
3. Подключённый источник или плагин — для приватных материалов пользователя или
   специализированной функции.
4. Отдельный MCP — когда нужен устойчивый доступ к системе, которой нет среди
   уже подключённых возможностей.

Перед применением проверить текущую установку, авторизацию, разрешения и область
доступа. Не считать наличие инструмента в интерфейсе подтверждением соединения.

## База знаний проекта

- Хранить устойчивую методику в `skill/education-project/references/`.
- Хранить пользовательские материалы в `sources/` или подключённом Google
  Drive; синхронизированные `sources/` не редактировать.
- Для одного чата прикреплять временный файл прямо к запросу, а не превращать
  его в постоянное правило.
- Для каждого внешнего источника сохранять прямую ссылку, дату проверки,
  область применимости и статус качества.
- Не помещать чувствительные ответы ученика в сторонний плагин без необходимости.

## Полезные подключения

Подключены по явному решению пользователя `2026-08-31`: `Consensus`,
`SciSpace`, `Wolfram`. Наличие инструментов подтверждено; при первом обращении
отдельно проверить, не требуется ли авторизация в аккаунте поставщика.

Локально создан `2026-09-01` проектный плагин `moex-futures-education` с MCP
`moex_futures_education`. Он предназначен только для чата «Фьючерсы», читает
официальный MOEX ISS и не содержит брокерских или торговых действий. Маршрут и
ограничения описаны в `topic-futures-sources.md`.

### Google Drive

Использовать для учебного журнала, таблицы прогресса, работ ученика и общей базы
материалов. Перед записью показать точный документ и диапазон изменений. Если
коннектор не установлен или не авторизован, использовать браузер только по
явной просьбе пользователя либо попросить подключить приложение.

### TickTick или календарь

Использовать один планировщик для интервальных повторений, экзаменов и учебных
блоков. Не создавать события или задачи без явного подтверждения расписания.
Предпочитать режим разрешений `читать без запроса, спрашивать перед записью`.

### Consensus

Использовать первым для быстрого поиска и синтеза рецензируемых работ,
библиографий и ответов на доказательные вопросы.
Проверять ключевые выводы по самой публикации и не смешивать препринт,
наблюдательное исследование и рандомизированный эксперимент.

### SciSpace

Использовать для глубокой работы с конкретными статьями и PDF, извлечения
методов и результатов, сравнительных таблиц и развёрнутых обзоров литературы.
Не дублировать обычный поиск Consensus: применять оба сервиса в одном запросе
только для проверки важного вывода или когда нужны их разные функции.

### Wolfram

Использовать для точной символьной математики, статистики, единиц, графиков и
независимой вычислительной проверки. Не показывать результат до самостоятельной
попытки ученика, если цель задания — проверить вычислительный навык. Не считать
Wolfram источником педагогического решения или торгового сигнала.

## Что не подключать по умолчанию

- торговые плагины и брокерское исполнение для учебного проекта;
- параллельный запуск нескольких академических поисковиков без цели сравнения;
- сервисы, которым требуется больше персональных данных, чем нужно задаче;
- автоматическую запись в календарь, таблицу или журнал без просмотра учеником;
- внешний MCP без понятного владельца, документации, политики данных и
  минимального набора разрешённых инструментов.

## Безопасные настройки MCP и плагинов

- Для источников знаний разрешать только чтение и поиск, если запись не нужна.
- Для планировщиков и документов спрашивать перед изменениями.
- Ограничивать список доступных инструментов MCP задачами проекта.
- Отключать неиспользуемые действия и хранить секреты только в предусмотренных
  переменных или OAuth, не в учебных материалах.
- После установки начинать новый чат, если продукт требует перезагрузки списка
  навыков или инструментов.
- При недоступности источника отмечать пробел, а не подменять его памятью модели.
